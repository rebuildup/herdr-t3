# ADR-0029: Artifacts surface — artifacts-v1 contract pin @d23205af and read-surface adoption

- Status: Accepted
- Date: 2026-11-28
- Program: issue #188 (T3 parity); ticket #396. Plugin-surface
  consumption of `rebuildup.artifacts`; same ADR-0011 `plugin_call`
  boundary as ADR-0012/0014/0016/0026/0027/0028.
- Pin: `rebuildup/herdr-plugins@d23205af0cd2ff7dba25f72e1f3b872762a108ee`
  = tag `v0.9.0`, contract `herdr-plugins.artifacts/v1` (STABLE since
  herdr-plugins v0.7.0; plugin `rebuildup.artifacts` v0.2.0+).
  Upstream spec: `herdr-plugins/docs/contracts/artifacts-v1.md`.

## Context

The artifacts plugin owns a registry of references to generated files
(HTML pages, images, PDFs, generic files): kind-specific validation at
register, a single-writer state index, read-time integrity annotations
(`missing_ref`/`owner_stale`/recomputed `oversize`), index-level
`orphans`/`corrupt` reporting, a `verify` health re-check, `deliver`
(path-in-prompt attachment), `gc` retention, and `export` — the
contract-designated client read surface. herdr-t3 needs the read side
so generated artifacts produced by other plugins (conversations,
handoffs, checkpoints) are discoverable in the GUI.

Unlike usage-v1, this contract is NOT read-only: `capability`
advertises `read_only: false` and
`mutation_commands: ["register", "delete", "deliver", "gc"]`.

## Decision

1. Consume the READ commands `capability`, `export`, `search`,
   `verify`. `export` is the eager per-machine read (the contract's
   designated client surface — same annotated records as `list` plus
   `returned`/`complete`/`filters` echo); `search` (metadata-only
   free text + `--since`/`--until` ISO bounds) and `verify`
   (read-only integrity report, `ok|corrupt|missing` + `issues[]` +
   `checks`) are lazy surface fetches — `verify` re-hashes every
   payload plugin-side so it is button-triggered, never polled.
   `list`/`get` stay unconsumed: `export` carries the identical
   annotated record shape.
2. Mutations stay OUT. `ARTIFACTS_MUTATION_COMMANDS` is an empty
   allowlist so `artifactsSupportsMutation` fails closed even though
   the contract advertises `register`/`delete`/`deliver`/`gc` — a
   future mutation ticket (e.g. `deliver` to a pane/agent) must
   extend the allowlist deliberately.
3. `src/shell/artifacts.ts` mirrors the `usage.ts` store shape:
   per-machine `{status, report, reportError}` state, defensive
   `*FromDoc` parsers that reject foreign contracts and malformed
   documents, the shared
   `not_installed|disabled|incompatible|unreachable|error`
   classification (`session_unreachable` maps to `unreachable`; other
   plugin-side kinds stay `error` with verbatim detail), a TTL-cached
   capability probe, and refresh on snapshot pushes (debounced),
   machine-status and machine-list changes via `initArtifacts()`.
   An export failure keeps the machine `ready` with `reportError`
   and last-good data.
4. Honesty rules rendered verbatim, never re-derived:
   `missing_ref`/`owner_stale`/`oversize` badges on each record,
   top-level `orphans`/`corrupt` id lists, verify `status`/`issues`/
   `checks` (null checks stay null), `complete:false` truncation echo.
   An empty registry renders as an honest empty state — producers
   may not exist yet.
5. `src/components/ArtifactsSurface.tsx` renders kind badges,
   `resolved_path` as truncated mono text with a copy affordance,
   storage mode, owner fields, and the verify report — T3 Code
   primitives and design tokens only. Artifact payloads are NEVER
   rendered inline: there is no shell-open bridge in herdr-t3 yet,
   so "open" is copy-then-open-external; `kind:"html"` additionally
   carries `meta.render {isolation:"required", policy:"client"}`
   and is link/copy-only — client-side isolated rendering with
   sandbox/CSP is a later concern per the contract safety boundary
   (the plugin never sanitizes).
6. The contract's record-session `--session NAME` filter is NOT
   emitted: the plugin CLI's top-level `parseArgs` consumes
   `--session` as the herdr session selector before command flags,
   so the flag can never reach the record filter — an upstream quirk
   recorded in the contract doc, not worked around.
7. Surface wiring follows the established right-panel pattern:
   `rightPanelStore` union + `isSurface`, `RightPanel`
   icons/titles/content/add-actions, `CommandMenu` and
   `WorkspaceHeader` entries, `initArtifacts()` in `App.tsx`.

## Consequences

- The artifacts gap narrows to "plugin-owned registry and integrity,
  GUI renders the read surface"; `deliver`/`gc`/`register` UI,
  inline/html preview with isolated rendering, a shell-open bridge
  for `resolved_path`, and producer plugins remain future tickets
  with their own contract review.
- `export`/`search`/`verify` each re-scan and re-annotate the index
  plugin-side per call; the surface debounces filter changes (400ms)
  and fetches lazily rather than polling.
- Contract pin is recorded here and in
  `docs/migration/contracts/plugin-artifacts.md` +
  `docs/migration/capabilities.json`; a future contract revision
  re-pins via a new ADR per the established rule.
