# ADR-0030: Handoffs surface — handoff-v1 contract pin @d23205af and read-only adoption

- Status: Accepted
- Date: 2026-12-08
- Program: issue #188 (T3 parity); ticket #404. Plugin-surface
  consumption of `rebuildup.handoff`; same ADR-0011 `plugin_call`
  boundary as ADR-0012/0014/0016/0026/0027/0028.
- Pin: `rebuildup/herdr-plugins@d23205af0cd2ff7dba25f72e1f3b872762a108ee`
  = tag `v0.9.0`, contract `herdr-plugins.handoff/v1` (**v1 stable**
  since herdr-plugins v0.6.0 / plugin v0.6.0). Upstream spec:
  `herdr-plugins/docs/contracts/handoff-v1.md`.

## Context

`rebuildup.handoff` owns handoff/delegation records: payload
*references* (conversations sessions, checkpoints, sibling handoff
records, external pointers — never transcript copies) bound to a
source pane/agent generation, a `pending|ready|delivered|done|failed|
superseded` lifecycle, execution targets (same-host and saved-machine
remote), provider native-resume metadata, and derived lineage
(`relationship{kind,parent_id}` with children computed by scan).
Records are produced by agents via the plugin CLI/MCP, so an empty
registry is the honest common case. T3 parity wants the records
visible; mutations (execute/delegate/merge-back) are explicitly a
separate ticket.

Unlike the other pinned plugin surfaces, this contract advertises
writes as **top-level commands** (`create`/`execute`/`delegate`/
`merge-back` in `commands`), not via a `mutation_commands` field.

## Decision

1. Consume the READ surface `list`, `status`, `resume-info` (+
   `capability` probe). `HANDOFF_MUTATION_COMMANDS` is an empty
   allowlist and `handoffsSupportsMutation` fails closed — the
   contract's mutation commands are top-level `commands`, so even a
   capability document advertising them can never make a mutation
   offerable. A future mutation ticket must extend the allowlist
   deliberately.
2. `src/shell/handoffs.ts` mirrors the `usage.ts` store shape:
   per-machine `{status, list, listError}` state, defensive
   `*FromDoc` parsers that reject foreign contracts and malformed
   documents, the shared
   `not_installed|disabled|incompatible|unreachable|error`
   classification, a TTL-cached capability probe requiring
   `list`/`status`/`resume-info` in `commands`, and refresh on
   snapshot pushes (debounced), machine-status and machine-list
   changes via `initHandoffs()`. Plugin-side kinds
   (`handoff_not_found`, `unsupported_strategy`, `other_session`,
   `remote_*`, …) stay `error` with verbatim detail.
3. `list` is the eager read (`--limit 500`, the contract maximum;
   `truncated`/`total`/`count` rendered verbatim). `status` is the
   on-demand detail read: it resolves payload refs through owner
   plugin CLIs and can be slow, so it is fetched only when a record
   is selected — always with `--no-reconcile`, because the contract's
   lazy `delivered → done` reconciliation persists plugin state and a
   read surface must not write. `--no-resolve-refs` is deliberately
   not passed: per-ref resolution verdicts
   (`resolved|missing_ref|unchecked|error|external` — `error` never
   collapsed into `missing_ref`) are the point of the detail view.
   `resume-info` is likewise on-demand behind an explicit Load toggle.
4. Honesty rules rendered verbatim, never re-derived:
   `transfer_check.state` (`ok|stale|unchecked` + the plugin's
   `reason`) — `unchecked` covers foreign-session records and
   unavailable snapshots and is never guessed stale; `target_check`
   and `remote_check` verdicts including
   `remote_target_requires_flag`/`remote_mismatch` (this client never
   passes `--remote`); `payload_resolution` states and `missing_refs`
   counts; `native_resume: unknown` in the resume table; payload ref
   kinds outside the v1 union survive with `kind` verbatim and null
   detail fields (additive tolerance). An empty `items` array is the
   honest empty registry — records have no in-GUI producer.
5. `src/components/HandoffsSurface.tsx` renders the record list
   (status/strategy badges, relationship kind, derived child count,
   staleness badge, execution target `target_pane_id` → hinted
   `target.pane_id`/`workspace_id` → `provider_hint`), a lazy
   `--status` filter, the on-demand status detail (source identity,
   target intent, lineage parent/children navigation, checks, payload
   resolutions, execution block), and the resume-info table — T3 Code
   primitives and design tokens only.
6. Surface wiring follows the established right-panel pattern:
   `rightPanelStore` union + `isSurface`, `RightPanel`
   icons/titles/content/add-actions, `CommandMenu` and
   `WorkspaceHeader` entries, `initHandoffs()` in `App.tsx`.

## Consequences

- Handoff records become visible per host with honest staleness and
  ref-resolution verdicts; the mutation surface (`create`/`execute`/
  `delegate`/`merge-back`, remote execution, `--remote` status) stays
  out until a dedicated ticket reviews it against the contract.
- `status` detail reads are O(owner-CLI) per selection — acceptable
  for an on-demand panel, never polled; snapshot pushes refresh only
  the cheap `list`.
- The `--no-reconcile` choice means a `delivered` record's lazy
  `done` transition is not triggered by viewing it; the record's
  persisted status and `execution.observed` are shown as stored, and
  `target_check` still reports the live target-pane verdict.
- Contract pin is recorded here and in
  `docs/migration/contracts/plugin-handoff.md` +
  `docs/migration/capabilities.json`; a future contract revision
  re-pins via a new ADR per the established rule.
