# ADR-0005: Distribution — native Electron desktop app

- Status: Accepted
- Date: 2026-11-22
- Supersedes: ADR-0004

## Context

Daily use requires a real desktop application: launchable from the Dock /
taskbar, with windows, menus, shortcuts and quit/restart semantics — not a
browser tab or PWA pointed at a manually started local HTTP server. T3
Code ships an Electron desktop app; herdr-t3 follows the same model so the
design system and interaction rules carry over unchanged.

The Bun bridge's herdr protocol work (public JSON RPC, private
`herdr-client.sock` attach codec, snapshot/event fan-out, terminal slot
management) is transport-agnostic and is reused. What changes is where it
runs and how the renderer reaches it.

## Decision

- The product is an **Electron app**: Main / Preload / Renderer, built per
  OS — `.app` on macOS, an installable package on Windows 11.
- The bridge core runs **in the Electron Main process**, connecting
  directly to the herdr socket (unix socket on macOS, named pipe on
  Windows). No Bun HTTP/WebSocket server is resident in production.
- The renderer keeps the React 19 + xterm.js UI and T3 design system
  unchanged. It never receives herdr operation authority directly: all
  herdr I/O goes through a typed preload bridge (contextBridge + IPC).
- One connection contract serves dev and production: the same
  `ClientFrame`/`ServerFrame` message shapes used by the WebSocket
  transport are carried over IPC in the desktop app. The WebSocket server
  remains only as a development/browser fallback sharing the same core.
- Dev and stable are separate apps: the dev build uses a distinct app id,
  userData dir and process identity, loads the Vite dev server (HMR), and
  defaults `HERDR_SOCKET` to an isolated test session; the stable build is
  fully self-contained and connects to the real herdr session.
- pc-setup remains the install/update authority for the stable app
  (install, update, verify, rollback per pc-setup#220 / ADR-0028). No
  in-app auto-updater competes with it.
- Linux keeps the herdr TUI; no Linux GUI package.

## Consequences

- `server/` is refactored into a transport-agnostic bridge core consumed
  by both the Electron Main process and the dev WebSocket server; the
  protocol codec and tests are unchanged.
- Signing/notarization and Windows installer warnings are handled per the
  actual packaging channel chosen for personal use (documented in
  pc-setup), not by inventing a store distribution.
- Real-session acceptance (existing panes visible to both TUI and GUI,
  attach I/O, agent state, session survival across app restarts) is a
  release gate on both macOS and Windows 11.
