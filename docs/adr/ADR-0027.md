# ADR-0027: Conversations surface — conversations-v1 contract pin @d23205af and read + index adoption

- Status: Accepted
- Date: 2026-11-26
- Program: issue #188 (T3 parity); ticket #374. Plugin-surface
  consumption of `rebuildup.conversations`; same ADR-0011 `plugin_call`
  boundary as ADR-0012/0014/0016/0026.
- Pin: `rebuildup/herdr-plugins@d23205af0cd2ff7dba25f72e1f3b872762a108ee`
  = tag `v0.9.0`, contract `herdr-plugins.conversations/v1` (STABLE
  since herdr-plugins v0.5.0). Upstream spec:
  `herdr-plugins/docs/contracts/conversations-v1.md`.

## Context

T3 Code parity tracks conversation/thread history as a first-class
surface; herdr exposes no transcript data itself. The
`rebuildup.conversations` plugin indexes provider-owned transcripts
(claude JSONL, codex rollout JSONL, opencode SQLite) into normalized
events without ever reading PTY text, and exposes honest read-time
verdicts (`stale`, `transcript_present`, `events_present`,
`status`/`error`) plus opaque-cursor paging. It is the data source the
planned usage surface (#364) also builds on.

## Decision

1. Consume the READ surface `capability`, `sessions`, `history`,
   `search`, plus the explicit `index` mutation. `show` (stable ref
   resolution) and `usage` (token/cost aggregation, #364) remain out
   of scope; `index`'s `--session`/`--socket`/`--timeout` targeting
   options stay plugin-side (the bridge already routes `plugin_call`
   to the owning host).
2. `src/shell/conversations.ts` mirrors the `automations.ts` store
   shape: per-machine `{status, sessions}` state, defensive
   `*FromDoc` parsers that reject foreign contracts and malformed
   documents (skipping bad entries rather than fabricating), the
   shared `not_installed|disabled|incompatible|unreachable|error`
   classification, and refresh on snapshot pushes (debounced),
   machine-status and machine-list changes via `initConversations()`.
   `session_unreachable`/`plugin_timeout` classify as `unreachable`;
   plugin `kind` values (`session_not_found`, `cursor_invalid`,
   `read_failed`, …) stay `error` with verbatim detail, and structured
   `error.hint` fields surface verbatim via `conversationsErrorHint`.
3. Paging cursors are opaque and passed back verbatim: `history
   --cursor` is a stringified byte offset, `search --cursor` a
   base64url per-session-offset token. The client never parses them;
   `restarted_sessions` and `malformed_lines`/`duplicates_skipped`
   page notes render as the plugin reports them.
4. Mutation gating differs from automations-v1: conversations-v1 DOES
   advertise `mutation_commands: ["index","refresh"]`, so
   `conversationsSupportsMutation` requires the command in the local
   `CONVERSATIONS_MUTATION_COMMANDS` allowlist AND the advertised
   `mutation_commands` set AND the flat `commands` list. `index` is
   non-destructive (plugin state only) so the surface offers an
   explicit "Index now" button with progress and plugin-reported
   counts — no confirm dialog. It carries the bridge-maximum 120s
   `timeout_ms` because transcript scanning can exceed the 15s
   default. `refresh` is the contract alias; the client always sends
   `index`.
5. `src/components/ConversationsSurface.tsx` renders the session list
   (provider, session id, cwd, event/turn counts, last activity) with
   verbatim status badges (`stale: <reason>`, `missing`/`error` +
   kind, `transcript missing`), expandable per-session event history
   via `history`, and a search box via `search`. Stale/missing states
   are shown exactly as the plugin computes them — the client never
   re-derives staleness. T3 Code primitives and design tokens only.
6. Surface wiring follows the established right-panel pattern:
   `rightPanelStore` union + `isSurface`, `RightPanel`
   icons/titles/content/add-actions, `CommandMenu` and
   `WorkspaceHeader` entries, `initConversations()` in `App.tsx`.

## Consequences

- The transcript-history gap narrows to "plugin-owned index, GUI
  renders sessions/events/search"; `show` ref resolution, `usage`
  aggregation (#364), and any transcript-authoring UI remain future
  tickets with their own contract review.
- Event payloads are bounded upstream (`MAX_TEXT_CHARS`/
  `MAX_INPUT_CHARS`); the index is navigational — full-fidelity
  history stays upstream/provider-owned, matching the contract's
  stated boundary.
- Contract pin is recorded here and in
  `docs/migration/contracts/plugin-conversations.md` +
  `docs/migration/capabilities.json`; a future contract revision
  re-pins via a new ADR per the established rule.
