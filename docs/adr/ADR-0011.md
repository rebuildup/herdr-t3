# ADR-0011: herdr-plugins contract consumption boundary

- Status: Accepted
- Date: 2026-11-25
- Amends: ADR-0009 (feature-parity data-source classes gain a fifth
  source); extends ADR-0006 (remote machines) to plugin execution.
- Program: issue #188; first tickets #219 (common boundary + Inbox v1),
  #220 (Git/Forge, contract-gated).

## Context

herdr-plugins (`rebuildup/herdr-plugins`) publishes versioned JSON CLI
contracts that own feature state on the herdr host — starting with
`rebuildup.inbox` v0.1.0 (`herdr-plugins.inbox/v1`,
`docs/contracts/inbox-v1.md` @ `f370b00`) and the Stage-1 development
contract `herdr-plugins.git/v1` (@ `414e87d`, not yet released).
herdr-t3 is the integration client (rebuildup/herdr-plugins#7,
rebuildup/pc-setup#239 for installation).

Issue #173 shipped settle/snooze as a localStorage overlay
(`herdr-t3:sidebar:agents:organize`). The plugin contract makes the
organize state host-owned and multi-client consistent; the localStorage
copy must not survive as a silent second source of truth.

## Decision

1. **Common plugin boundary (server-side).** The bridge exposes two
   machine-scoped frame types: `plugin_list` (installed-plugin discovery
   via `herdr plugin list --json` on the target host) and `plugin_call`
   (one contract command as argv). Both answer on the existing
   `rpc_result` channel, tagged with `machine`.
2. **Execution happens on the host that owns the herdr session.** Local
   machine: direct `spawn`. SSH machines: the same argv runs through the
   existing ssh transport (`sshExec` path in `server/ssh.ts`) on the
   remote host — never through the forwarded-socket path the contract
   forbids, and never by reading plugin state files. Plugin state files
   are never opened by herdr-t3.
3. **No shell interpolation.** Remote argv is quoted per-OS (POSIX
   `shellQuote`, Windows PowerShell encoded script, mirroring
   `remoteBridgeCommand`). Client input is `args: string[]` elements
   only.
4. **Discovery → capability → call.** `plugin_call` resolves the plugin
   entry (`plugin_id`, `enabled`, `plugin_root`), verifies the contract
   via the plugin's own `capability` command (cached), then executes
   `<plugin_root>/src/cli.ts <command> [args]` with `bun run` from
   `plugin_root`. Contract failures (`ok:false` on stderr, exit 1/2),
   transport failures, timeouts and unsupported commands stay distinct
   error codes; nothing is reported as an empty success. The
   `capability` meta-command is always permitted (issue #539): the
   capability probe itself already proved the CLI answers it, and
   upstream contracts are not required to list it in `commands` — every
   other command still requires explicit `commands` membership. The
   capability cache is keyed by plugin `version` so an upstream plugin
   update can never be served a stale document inside the TTL window.
5. **Session targeting.** Every plugin exec targets the same
   Host/Session the bridge itself uses; nothing falls back to ambient
   or default resolution (amended for issue #289). Local machine: the
   host forwards the bridge's resolved API socket
   (`herdrSocketPath()` — `HERDR_SOCKET` env or the default socket) —
   plugin CLIs get it as `--socket PATH` (upstream `socketFor` gives an
   explicit socketPath precedence over `HERDR_SOCKET_PATH`,
   `--session`/`HERDR_SESSION` and the default socket), and
   `herdr plugin list` discovery gets it as `HERDR_SOCKET_PATH`, which
   the herdr CLI applies *after* the `PLUGIN_ENV_SCRUB` removal since
   the herdr CLI has no `--socket` flag. SSH machines keep the
   session-name mechanism: non-`default` saved sessions are passed as
   `--session` to plugin CLIs *and* to the discovery `herdr` argv
   (`herdr --session <name> plugin list`), so discovery cannot silently
   read the remote default session either; `default` adds no flags
   (the plugin's `resolveSocketPath` maps a named session to
   `sessions/<name>/herdr.sock`; `default` must use the implicit
   default socket).
6. **Freshness without polling.** The client refetches `inbox list` on
   session-snapshot pushes (debounced), after every mutation, and on
   machine online transitions. `watch`/resident processes are not used.
7. **Organize-state ownership.** `rebuildup.inbox` on the target host is
   the canonical store for settle/snooze/restore. The GUI keeps only
   display preferences (shelf collapse, theme). herdr remains the sole
   execution-state source; the plugin never writes agent status and the
   GUI never fabricates it.
8. **#173 localStorage migration.** Legacy records migrate once per
   machine, only after that machine's inbox capability is confirmed:
   `settled` → `settle`; `snoozed` → `snooze` without `--until` (honors
   the plugin's `defaultSnooze` config), falling back to `settle` when
   the plugin reports a usage error (no configured default). Rationale:
   the plugin's `snooze` requires a deadline the legacy record never
   had, and a far-future `--until` would leave a decade-long `_wake`
   process per pane; `settle` preserves the exact auto-return semantics
   (clears on `state_change_seq` advance). Migrated machines have their
   keys removed from localStorage; records for machines without the
   plugin stay dormant and are never read (no silent local fallback).
   An upstream request for an indefinite-snooze equivalent is tracked
   separately.
9. **Attention is never hidden.** Plugin items with `attention: true`
   (`blocked`) are excluded from the organize projection, matching the
   plugin's `in_inbox` semantics; `partitionAgents` additionally refuses
   to shelf a `blocked` row even if a stale record exists.
10. **Unavailable is a state, not an error to hide.** Per machine the
    client distinguishes `not_installed` / `disabled` / `incompatible`
    (contract mismatch, missing commands, or — since issue #539 — a
    `min_herdr_version` newer than the machine's reported herdr
    version) / `unreachable` / `plugin_error`. Organize actions are
    disabled with the reason surfaced; shelves simply show no organized
    rows — never a fabricated empty success. Version skew is classified
    client-side from `plugin_list`'s `min_herdr_version` against the
    machine's reported herdr version; unknown on either side never
    blocks a surface.

## Consequences

- `AGENTS.md` §5 scope boundary is further amended: consuming published
  plugin contracts is in scope; the parity inventory's `[cli]` class is
  superseded by plugin contracts where a plugin owns the capability
  (direct `gh`/`git` implementations must not duplicate plugin-provided
  features — #220).
- The bridge gains a host-exec path independent of the herdr socket;
  it is argv-only, bounded by timeout, and carries no secrets.
- Inbox organize state becomes consistent across herdr-t3 instances and
  the herdr TUI/plugin hooks; #173's per-browser localStorage state is
  retired by migration, not dual-written.
- Git/Forge (#220) reuses this boundary; unpublished contracts
  (`herdr-plugins.git/v1` Stage 1) are adopted only after a published
  tag/SHA and capability are recorded. Stage-1 read-only commands
  (`status`/`diff`/`project`) are consumed at pinned contract SHA
  `414e87dea9faa5c221fb27508e5828f086849836` ahead of publication —
  the pin, not a tag, is the recorded adoption point; mutation and forge
  surfaces stay gated on published contract versions (#227–#229).
