# ADR-0015: Projects/Scripts — projects-v1 schema v2 re-pin (run ownership + stop confirmation)

- Status: Accepted
- Date: 2026-11-25
- Amends: ADR-0014 (projects-v1 adoption point); same re-pin rule as
  ADR-0012 for git-v1.
- Program: issue #188; ticket #259. Upstream: rebuildup/herdr-plugins#66
  (merged to release-0-3-0 @ `b0c8c60`).

## Context

`docs/contracts/projects-v1.md` advanced after the ADR-0014 pin
(`c8460283`). The scripts runner run records are now **schema v2**:

- New `ScriptRun` fields: `host`, `session_key` (the
  `sessionKeyFor` discriminator: hostname + canonical socket path),
  `stop_requested_at`. v1 records load them `null` and are verified by
  pane context only — backward-compatible parsing is required.
- New `result` states: `stopping` (stop requested, exit unconfirmed)
  and `stop_unconfirmed` (bounded confirmation window elapsed without
  evidence). The active set is now `running | stopping |
  stop_unconfirmed`; ctrl+c alone is never treated as stopped.
- Ownership tuple (host + session_key + pane_id + workspace/tab +
  started_at) is re-validated via `pane.get` before ANY
  input/close/read. Foreign or mismatched panes yield a structured
  `stale_pane` outcome / `unknown` record with **zero pane side
  effects**; foreign-host records are never probed through the wrong
  socket.
- `scripts stop` outcomes gain `stale_pane` and `stop_unconfirmed`
  actions alongside `stopped | already_finished | pane_gone`.
  `no_running_runs` still fails when no run was acted on.
- `scripts results` reconciles active records lazily after ownership
  re-validation (vanished pane: `running` → `unknown`, stopping states
  → `stopped`; empty foreground process list also promotes to
  `stopped`). `scripts logs` reads only after ownership validation.

The registry surface (`list`/`show`/`discover`/`register`/`update`/
`settings`/`repos`) is unchanged by this contract revision.

## Decision

1. **Re-pin**: herdr-t3 consumes `herdr-plugins.projects/v1` as
   implemented at `rebuildup/herdr-plugins@b0c8c60` (release-0-3-0,
   schema v2). The contract name/suffix is unchanged; the pin, not a
   moving branch, remains the adoption point (ADR-0011/0012/0014
   rule). ADR-0014 stays accepted for scope; this ADR records only the
   new pin and the v2 semantics delta.
2. **Backward-compatible parsing**: `ScriptRun` gains `host`,
   `session_key`, `stop_requested_at` as nullable fields; absent fields
   (v1 records) parse as `null`, never as fabricated values.
3. **Honest in-flight rendering**: `stopping`/`stop_unconfirmed` are
   warning-state, non-terminal results — the UI shows them as stop
   confirmation in flight (with `stop_requested_at`), never as success
   or plain failure, and `scripts stop` stays available for every
   active-set result (`running | stopping | stop_unconfirmed`).
4. **`stale_pane` classified distinctly**: a `stale_pane` stop action
   or record `error` is labelled as an ownership mismatch with zero
   pane side effects — never collapsed into a generic failure or
   success. The client performs no pane operations itself; all
   re-validation is plugin-side.
5. **Unchanged scope**: auto triggers remain upstream-gated
   (herdr-plugins#60); checkpoints remain out (herdr-plugins#4). The
   registry dialog needs no functional change.

## Consequences

- `docs/migration/contracts/plugin-projects.md`,
  `docs/migration/capabilities.json`, and `docs/design/t3-parity.md`
  record the `@b0c8c60` pin.
- Hosts running the older `@c8460283` plugin keep working: v1 records
  and the old result/action sets parse unchanged; the new states simply
  never appear.
- Upstream residuals #67 (shell portability), #68 (durable
  collection), #69 (audit items) stay tracked upstream — no silent
  workarounds here.
