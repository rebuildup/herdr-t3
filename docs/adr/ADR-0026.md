# ADR-0026: Automations surface — automations-v1 contract pin @6c1cfa5 and read-only adoption

- Status: Accepted
- Date: 2026-12-02
- Program: issue #188 (T3 parity); ticket #361. First plugin-surface
  consumption of `rebuildup.automations`; same ADR-0011 `plugin_call`
  boundary as ADR-0012/0014/0016.
- Pin: `rebuildup/herdr-plugins@6c1cfa501323772e7c1c008c3dbcd7e364feb0b3`
  = tag `v0.7.0`, contract `herdr-plugins.automations/v1` (STABLE,
  herdr-plugins #147). Upstream spec:
  `herdr-plugins/docs/contracts/automations-v1.md`.

## Context

T3 Code parity inventory lists scheduled tasks as plugin-owned
capability with no herdr analog (`docs/design/t3-parity.md`). The
`rebuildup.automations` plugin shipped the stable v1 contract —
scheduled and event-triggered agent prompts with honest run history,
lazy missed-run derivation, and driver coverage reporting. It is the
first plugin surface with zero cross-plugin dependencies whose read
commands (`list`/`get`/`runs`) return complete honest data without any
execution side effects, making it the right first slice (parent
handoff: herdr-plugins#7 / pc-setup#239).

## Decision

1. Consume the READ surface only: `capability`, `list`, `get`, `runs`.
   Mutations (`create`/`update`/`set-enabled`/`delete`/`run-now`/
   `reconcile`) and driver commands (`fire`/`tick`/`watch`/`schedule`)
   are explicitly out of scope — `reconcile` materializes missed runs
   (a write) and driver commands are long-running or execute prompts,
   outside the `plugin_call` timeout envelope. A later mutation ticket
   must re-check `capability.commands` (v1 has no
   `mutation_commands`; gating uses the flat `commands` list).
2. `src/shell/automations.ts` mirrors the `inbox.ts` store shape:
   per-machine `{status, tasks}` state, defensive `*FromDoc` parsers
   that reject foreign contracts and malformed documents, the shared
   `not_installed|disabled|incompatible|unreachable|error`
   classification, and refresh on snapshot pushes (debounced),
   machine-status and machine-list changes via `initAutomations()`.
3. `src/components/AutomationsSurface.tsx` renders task rows
   (name/schedule summary/`next_run_at`/`enabled`/`driver.state`/
   `missed_total`) with expandable per-task run history fetched via
   `runs`. Derived missed runs (`run_id:null`, `derived:true`) are
   labelled derived — never shown as executed. T3 Code primitives and
   design tokens only.
4. Surface wiring follows the established right-panel pattern:
   `rightPanelStore` union + `isSurface`, `RightPanel`
   icons/titles/content/add-actions, `CommandMenu` and
   `WorkspaceHeader` entries.

## Consequences

- The scheduled-tasks parity gap narrows to "plugin-owned, GUI renders
  read-only"; mutation UX and any driver management remain future
  tickets with their own contract review.
- `webhook` schedules stay `unsupported_schedule` upstream
  (herdr-plugins ADR-0026); the client renders the type verbatim.
- Contract pin is recorded here and in
  `docs/migration/contracts/plugin-automations.md` +
  `docs/migration/capabilities.json`; a future contract revision
  re-pins via a new ADR per the established rule.
