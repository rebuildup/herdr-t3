# ADR-0020: Projects/Scripts — projects-v1 re-pin @2dcb2abf (shell families + audit convergence)

- Status: Accepted
- Date: 2026-11-25
- Amends: ADR-0014/ADR-0015/ADR-0019 (projects-v1 adoption point); same
  re-pin rule as ADR-0012/ADR-0015/ADR-0018/ADR-0019.
- Program: issue #188; ticket #269. Upstream: rebuildup/herdr-plugins#67
  + #69 (merged to release-0-3-0 @ `2dcb2abf`).

## Context

`docs/contracts/projects-v1.md` advanced after the ADR-0019 pin
(`3b28349`). Two upstream changes land together:

- **#67 shell families.** `scripts run` gains
  `[--shell auto|sh|cmd|powershell]` (`auto` = detect; anything else →
  `invalid_shell`). The shell family is resolved flag →
  `pane.process_info` foreground → conservative host-OS default
  (recorded `shell_source:"host_default"`, never silent). A positively
  identified unsupported shell fails `shell_unknown`; a non-shell
  foreground fails `not_a_shell` — both abort BEFORE injection, close
  the just-created pane, and persist NO run record. `ScriptRun` gains
  `shell_family` ∈ `sh|cmd|powershell` and `shell_source` ∈
  `flag|process_info|host_default` (both `null` on pre-#67 records).
  Injection is now two `pane.send_input` lines (command + per-family
  marker echo), and over-long/multiline commands become
  `runs/<id>.sh|.cmd|.ps1` script files; `command_line` records both
  lines.
- **#69 audit convergence.** Remote identity keeps path case verbatim
  (case-sensitive forges; host still lowercased, non-default port
  kept); `has_submodules` is tri-state (probe failure → `null` =
  unknown, never guessed `false`); a corrupt settings file reads as
  empty and the next `set`/`unset` rewrites it wholesale — no
  `settings_corrupt` error.

## Decision

1. **Re-pin**: herdr-t3 consumes `herdr-plugins.projects/v1` as
   implemented at `rebuildup/herdr-plugins@2dcb2abf` (release-0-3-0).
   The contract name/suffix is unchanged; the pin, not a moving branch,
   remains the adoption point (ADR-0011 rule).
2. **Null-tolerant parsing**: `shell_family`/`shell_source` parse as
   nullable strings; absent fields (pre-#67 records) read `null`, and
   unrecognized future values pass through verbatim rather than being
   fabricated away (same tolerance as `result`).
3. **`--shell` argv**: `scripts run` emits `--shell <family>` only for
   an explicit `sh|cmd|powershell` selection; `auto`/absent omits the
   flag so the plugin's detection chain and `shell_source` recording
   apply. Family values never start with `-`, so the separate
   `--name value` pair is always safe under upstream strict parsing
   (no `--name=value` fallback needed).
4. **Distinct classification**: `shell_unknown`, `not_a_shell`, and
   `invalid_shell` join the preserved plugin `error.kind` sets. They
   are pre-injection aborts / argument errors — plugin errors, never
   run-record failures — and the dialog labels them accordingly.
5. **UI honesty**: the scripts dialog offers an explicit shell
   selector (default `auto`); run records display `shell_family` +
   `shell_source`, with `host_default` rendered as an auto-detected
   host default, not a user choice. `has_submodules: null` renders as
   "submodules unknown", distinct from a probed `false`; remote
   identities are displayed/compared verbatim.
6. **Spec updated**: `docs/migration/contracts/plugin-projects.md`
   bumps to Version 3 and records the `--shell` flag, the two-line
   injection, the new record fields, the new error kinds, and the #69
   audit semantics.

## Consequences

- Older plugin revisions keep working for everything except explicit
  shell selection: omitting `--shell` is valid on both revisions, and
  pre-#67 run records parse with `shell_*` = `null`.
- `shell_unknown`/`not_a_shell` surface as request-time plugin errors
  with no run record — the UI must not look for a `failed` record.
- Selecting an explicit shell on a pre-#67 plugin yields an honest
  plugin `usage`/unknown-flag error, not a silent mis-parse.
- ADR-0014 scope and ADR-0015/ADR-0019 schema-v2 + receipt decisions
  stand; run records remain schema v2 with additive nullable fields.
