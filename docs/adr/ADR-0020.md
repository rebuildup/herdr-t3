# ADR-0020: Checkpoints — checkpoints-v1 re-pin @55df8d0a and work-unit auto-capture adoption

- Status: Accepted
- Date: 2026-11-25
- Amends: ADR-0016/ADR-0017 (checkpoints-v1 adoption point); same re-pin
  rule as ADR-0012/ADR-0015/ADR-0018/ADR-0019.
- Program: issue #188; ticket #268; groundwork #221. Upstream:
  rebuildup/herdr-plugins#74 (merged to release-0-4-0 @ `55df8d0a`).

## Context

`docs/contracts/checkpoints-v1.md` advanced after the ADR-0017 pin
(`c8dc3b3`). The contract gained work-unit auto-capture:

- Checkpoint entries gain `kind`: `"manual"` (explicit `create`),
  `"auto"` (lazy work-unit drain or `create --auto`),
  `"pre_restore"` (mandatory pre-restore safety capture). Entries
  written before #74 carry no `kind` and are treated as `"manual"`.
- `create --auto` records `kind:"auto"`; an explicit pane-targeted
  `create` clears that pane's pending auto-capture mark (the manual
  capture supersedes it).
- The plugin registers `pane.agent_status_changed` /
  `pane.closed` event hooks that only write capture-pending marks;
  EVERY command except `capability`/`help` lazily drains them before
  its own work. Drain outcomes appear as `auto_captures` on the
  payload (omitted when empty):
  `{captured:[ids], skipped:[{pane_id,reason}], session_unreachable}`.
  `skipped[].reason` is `stale_generation`, `pane_or_agent_gone`,
  `no_pane_cwd` or a git/checkpoint error kind. Auto-capture never
  fails the command; an unreachable session sets
  `session_unreachable` and leaves marks pending.
- After pane-targeted captures the plugin projects display-only
  `checkpoint_latest`/`checkpoint_count` pane metadata tokens
  (source `rebuildup.checkpoints`); best-effort, never fails the
  command. This client does not consume them.
- Granularity is herdr `agent_status` — a **work-unit** checkpoint,
  deliberately coarser than per-turn; no per-message turn signal
  exists upstream (recorded as an upstream gap in
  herdr-plugins `docs/specs/checkpoints.md`).

## Decision

1. **Pin**: herdr-t3 consumes `herdr-plugins.checkpoints/v1` as
   implemented at `rebuildup/herdr-plugins@55df8d0a` (release-0-4-0),
   superseding the `c8dc3b3` pin. Older plugin builds simply omit
   `kind`/`auto_captures`/`--auto`; the parsers treat absent fields as
   pre-#74 semantics (`kind` → `"manual"`, no drain report).
2. **Parse honestly**: `kind` is preserved verbatim for unknown
   future values (open-string union) rather than relabelled; absent
   means `"manual"` per contract. `auto_captures` is parsed on every
   command document (`capability` never carries it) and exposed as
   `auto_captures: AutoCapturesReport | null` on every result type; a
   present-but-empty block normalizes to null, matching the contract's
   omit-when-empty rule.
3. **Surface, never swallow**: drain outcomes render wherever a
   command result is shown — the list fetch, create/delete notices,
   the restore dialog (`plan` preview and restore result), the detail
   `show` fetch and the diff pane — as captured count, per-pane skip
   reasons and a `session_unreachable` note. `skipped[].reason` stays
   a free-form string so new upstream reasons stay visible.
4. **Kind badge**: list rows badge non-`manual` kinds (`auto`,
   `pre_restore`, unknowns); the detail pane shows the full `kind`
   field for every entry. No per-turn claims anywhere — copy says
   "work-unit".
5. **`create --auto` as explicit opt-in only**: the create form gains a
   `Switch` labelled "Record as auto" that appends `--auto` and is
   described honestly — it only labels the entry `kind:"auto"` for
   agent-detected work-unit boundaries; it does not change when
   checkpoints are taken and fabricates no agent-driven trigger.
6. **Pane metadata not consumed**: `checkpoint_latest`/
   `checkpoint_count` are display-only projections owned by herdr
   pane metadata; the checkpoints surface does not read or depend on
   them.

## Consequences

- Hosts on `c8dc3b3` keep working unchanged (no `kind`, no
  `auto_captures`, no `--auto`); pc-setup hosts need the re-pinned
  plugin build for auto-capture entries and `--auto`.
- Every plugin command the dialog issues can now return
  `auto_captures`; UI surfaces it on all result paths so a drain is
  never invisible.
- Remaining upstream non-goals are unchanged: no per-turn (per-message)
  auto-capture, no multi-repo orchestration, no checkpoint GC, no
  private object store/quarantine, no submodule worktree
  capture/restore (herdr-plugins#75+).
