# ADR-0017: Checkpoints — checkpoints-v1 re-pin @c8dc3b3 and plan/restore adoption

- Status: Accepted
- Date: 2026-12-02
- Amends: ADR-0016 (checkpoints-v1 adoption point); same re-pin rule as
  ADR-0012/ADR-0015.
- Program: issue #188; ticket #264; groundwork #221. Upstream:
  rebuildup/herdr-plugins#73 (merged to release-0-4-0 @ `c8dc3b3`).

## Context

`docs/contracts/checkpoints-v1.md` advanced after the ADR-0016 pin
(`4aab1a7`). The contract gained two commands and new error kinds:

- `plan <id> [--repo PATH]` — read-only restore preview:
  `{plan:{files_to_change, untracked_to_delete, already_matches},
  warnings}` plus the `ref` probe. `untracked_to_delete` counts files
  the post-restore `git clean -fd` passes would **permanently
  delete**; the UI must label that explicitly.
- `restore <id> [--repo PATH] [--force]` — safe restore: hidden-ref
  existence check → shared-worktree isolation via herdr
  `session.snapshot` (≥2 panes under the repo root → `shared_worktree`
  with `error.panes`; unreachable session → `session_unreachable`;
  `--force` bypasses and reports `isolation:"forced"` + warning) →
  mandatory `pre-restore:<id>` checkpoint persisted **before** any
  mutation (capture failure refuses the restore) →
  `git restore --source --worktree --staged` + up to 4 `git clean -fd`
  passes → post-verify.
- Success payload: `restored_commit`, `pre_restore:{id,ref,commit,
  label}`, `isolation`, `sharing_panes`, `clean_passes`, `warnings`
  (submodule gitlinks are recorded but NOT restored — root repo only).
- Mutation-phase failures carry `pre_restore_checkpoint_id` /
  `pre_restore_ref` / `pre_restore_commit` so callers can recover via
  `restore <pre-restore-id>`.
- New error kinds: `repo_mismatch`, `checkpoint_ref_missing`,
  `shared_worktree` (`error.panes`), `session_unreachable`,
  `restore_failed` / `clean_failed` / `clean_incomplete` /
  `restore_verify_failed`.
- `mutation_commands` is now `["create","delete","restore"]`;
  `commands` adds `plan`.
- `--repo` may select another worktree of the SAME repository only
  (shared git common dir); anything else is `repo_mismatch`. Default
  target is the checkpoint's recorded `repo_root`.

Two contract error extras are new to the bridge boundary: `error.panes`
and the `pre_restore_*` fields. They are non-secret identifiers and are
added to `ERROR_FIELD_ALLOWLIST` in `server/plugins.ts` (issue #257
mechanism); caps, depth and secret exclusions are unchanged.

## Decision

1. **Pin**: herdr-t3 consumes `herdr-plugins.checkpoints/v1` as
   implemented at `rebuildup/herdr-plugins@c8dc3b3` (release-0-4-0),
   superseding the `4aab1a7` pin for the commands this surface uses.
   Older plugin builds simply do not advertise `plan`/`restore` and
   render capability-gated "not supported" states.
2. **Plan before restore**: the restore dialog fetches `plan` on open
   (and on explicit refresh after a `--repo` override) and gates the
   Restore button on a successful preview. `untracked_to_delete > 0`
   renders an explicit permanent-deletion warning; `already_matches`
   and `ref.exists:false` render honestly.
3. **Explicit target**: the dialog shows the checkpoint's `repo_root`
   as the default target and offers an optional `--repo` override
   limited to same-repository worktrees; `repo_mismatch` surfaces as a
   plugin error, never retried against another repo.
4. **No implicit force**: `shared_worktree` and `session_unreachable`
   render the plugin's `panes` ids and offer "Force restore anyway" as
   a separate destructive-labelled action — the only path that appends
   `--force`. There is no automatic retry and no force-on-error.
5. **Recovery path**: mutation-phase failures surface
   `pre_restore_checkpoint_id`/`pre_restore_ref`/`pre_restore_commit`
   with an "Open pre-restore checkpoint" affordance that selects the
   backup entry so the user can inspect/restore it through the normal
   gated flow. Successful restores show `pre_restore` info,
   `isolation`, `sharing_panes` and `clean_passes` verbatim.

## Consequences

- `ERROR_FIELD_ALLOWLIST` gains `panes`, `pre_restore_checkpoint_id`,
  `pre_restore_ref`, `pre_restore_commit`; boundary tests pin that
  non-allowlisted keys (e.g. `env`) still do not cross.
- pc-setup hosts need the re-pinned plugin build for restore; hosts on
  `4aab1a7` keep list/show/diff/create/delete unchanged.
- Remaining upstream non-goals are unchanged: no turn-boundary
  auto-capture, no multi-repo orchestration, no checkpoint GC, no
  submodule worktree restore (herdr-plugins#74–#75).
