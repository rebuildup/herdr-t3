# ADR-0017: Source Control surface — git-v1 re-pin @d057830 (strict option parsing)

- Status: Accepted
- Date: 2026-11-25
- Amends: ADR-0012 (git-v1 adoption point); same re-pin rule — the pin,
  not a moving branch, is the adoption point.
- Program: issue #188; ticket #265. Upstream: rebuildup/herdr-plugins#64
  (merged to release-0-2-0 @ `d057830`).

## Context

`docs/contracts/git-v1.md` advanced after the ADR-0012 pin (`62309b9c`).
The contract suffix `herdr-plugins.git/v1` and every response shape are
unchanged; what changed is **argument handling**:

- **Strict option parsing:** every `-`-prefixed token must be a flag the
  command documents — unknown options are usage errors, never silently
  ignored. `pr` flags are whitelisted per action. Boolean flags reject
  `=value`; value flags accept both `--name value` and `--name=value`
  (the `=` form is required for values that themselves start with `-`).
  `--` ends option parsing; extra positionals are usage errors. Global
  flags (`--session`, `--socket`, `--timeout`) accept the same `=` form
  and are validated.
- **Exit codes are now contractual:** `0` success; `1` handled
  runtime/environment failure (`error.kind` carries `git_error`,
  `git_missing`, `timeout`, `not_a_repo`, `bare_repo`, `pane_not_found`,
  `no_pane_cwd`, `gh_missing`, `gh_error`, `error`); `2` usage error
  (`error.code == "usage"`, no `kind`).
- `stage`/`unstage` bare invocation and the `--all` + `--path`
  combination are usage errors; `commit` without a non-empty `-m` is a
  usage error, not a git failure.

Two client-visible consequences:

- A `-`-leading flag value sent as a separate argv element is now
  reliably a usage error — and a bare `--session`/`--timeout`/`--socket`
  token would be eaten by the plugin's global-flag pre-scan before
  command parsing. Values that can start with `-` (commit messages,
  `--grep`/`--author`/`--body`, …) must travel as `--name=value`.
- A usage error is OUR argv bug or a contract mismatch, not a
  repository state — it must render distinctly from `git_error`.

## Decision

1. **Re-pin**: herdr-t3 consumes `herdr-plugins.git/v1` as implemented
   at `rebuildup/herdr-plugins@d057830` (release-0-2-0). Response
   parsers are unchanged; only argv construction and error
   classification are affected.
2. **`--name=value` for dash-leading values**: every argv builder in
   `src/shell/git.ts` routes value flags through one helper that emits
   the `=` form whenever the value starts with `-`. Normal values keep
   the separate form (documented, and pinned by tests).
3. **Positional arity audited**: `[remote] [refspec]` on `push` is
   positional — a refspec without a remote would bind as the remote.
   `gitPushArgs` now rejects that combination client-side with a
   `usage`-coded error instead of emitting a mis-bound argv.
4. **Usage errors stay distinct**: the bridge already preserves
   `error.code == "usage"` (no `kind`) end-to-end —
   `server/plugins.ts` `outcomeToJson` prefers `kind` when present and
   falls back to `code`, so exit-2 surfaces as ApiError code `usage`,
   classified by `classifyGitError`/`classifyForgeError` into
   `repo_error` code `usage`. The Git dialog labels it "plugin usage
   error" rather than a git failure.

## Consequences

- Hosts on the older `62309b9c` build keep working: the `=` form was
  already accepted by `flagValue`/`flagValues`, and unknown-option
  rejection only makes previously-tolerated typos fail loudly.
- `pr create --body-file -` now travels as `--body-file=-`; the plugin
  reads it identically (stdin marker).
- No response-shape, capability, or gating changes; ADR-0012 scope and
  decisions stand.
