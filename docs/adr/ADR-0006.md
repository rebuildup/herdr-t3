# ADR-0006: Remote machines — saved SSH endpoints over herdr's own bridges

- Status: Accepted
- Date: 2026-11-22
- Supersedes: none (extends ADR-0005)

## Context

Daily herdr use spans several machines: the local host plus saved SSH
machines (WSL, Windows, Linux servers) that Herdr itself already manages.
Herdr stores them in its own registry
(`~/.local/state/herdr/client/endpoints.json`, exposed by
`herdr machine list/add/status/reconnect` and `--machine`) and reaches them
through SSH stdio bridges, not port forwarding.

Two transport facts constrain the design:

- `ssh -L` forwarding is not reliable: user SSH configs may set
  `ClearAllForwardings yes` (the maintainer's `device-*` hosts do), which
  silently drops `-L`. Herdr itself therefore multiplexes its IPC protocol
  over the SSH process's stdin/stdout (`SshStdioBridge`).
- The remote herdr binary exposes two hidden bridge commands:
  - `herdr --session <s> remote-api-bridge` — one JSON-lines request per
    process on stdin/stdout; `events.subscribe` stays open as a long-lived
    stream. Advertises capability `herdr-api-bridge-v1`.
  - `herdr --session <s> remote-client-bridge` — a raw byte pipe of the
    private `herdr-client.sock` bincode protocol, i.e. the exact transport
    herdr-t3's `client-link.ts` already speaks for terminal attach.

## Decision

- **Reuse herdr's machine registry.** The app reads
  `endpoints.json` (plus `herdr machine list --json` for refresh) and never
  keeps its own machine list, remote agent runtime, or resident remote
  daemon. Adding a machine shells out to `herdr machine add`; removing or
  re-authenticating stays a herdr CLI operation the GUI surfaces but does
  not reimplement.
- **Per-machine bridge sessions.** Each enabled machine gets its own
  bridge session (snapshot/events/RPC) and terminal slots, exactly like the
  local endpoint. One machine's failure never affects the others.
- **Transports:**
  - API: one `ssh` exec of `remote-api-bridge` per RPC call; one
    long-lived exec for `events.subscribe`. Requests/responses are the
    same newline-delimited JSON contract as the local socket.
  - Terminal attach: one `ssh` exec of `remote-client-bridge` per attach;
    the child process's stdio is adapted to the same byte-stream contract
    `client-link.ts` uses for unix sockets / named pipes.
- **ID namespacing.** Every client frame may carry `machine` (default
  `local`); every snapshot/event/terminal frame is tagged with its machine
  so the renderer can keep per-machine state and never route a pane id
  from one machine to another.
- **SSH policy.** Authentication, `known_hosts`, keys and agent forwarding
  are delegated to OpenSSH and the user's SSH config. The app runs ssh
  with `BatchMode=yes`: interactive prompts (password, host-key
  confirmation, remote install approval) are never auto-answered — they
  surface as `auth_required` / `error` states with the exact remediation
  command (`herdr machine reconnect <label>`).
- **Remote herdr resolution.** Prefer the executable recorded in herdr's
  `ssh-metadata` cache; fall back to a remote PATH probe and common install
  paths. Windows remotes are detected and reported explicitly rather than
  silently failing (named-pipe hosts need the PowerShell streaming
  variant; tracked as follow-up work).
- **Connection lifecycle.** Machines connect lazily on selection and can
  be disconnected/reconnected independently. Reconnect always re-fetches
  the snapshot and re-attaches terminals; nothing typed during an outage
  is sent automatically (existing draft semantics are preserved per
  machine).

## Consequences

- RPC latency to remote machines is one SSH round-trip per call (mitigated
  by SSH `ControlMaster`/`ControlPersist` connection reuse). Snapshot and
  event traffic are long-lived streams and unaffected.
- Terminal attach over `remote-client-bridge` is the same protocol the
  herdr TUI uses for saved machines, so attach/scroll/resize semantics are
  identical to local panes.
- Machines whose remote herdr is missing or incompatible get an explicit
  status (`error`/`incompatible`) with the remediation command, instead of
  an empty UI.
- Linux GUI packaging remains out of scope (ADR-0005); this ADR covers
  macOS/Windows clients reaching remote herdr hosts of any supported OS.
