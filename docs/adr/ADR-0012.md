# ADR-0012: Source Control surface — git-v1 contract pin and capability gating

- Status: Accepted
- Date: 2026-11-25
- Extends: ADR-0011 (plugin consumption boundary); amends the git-v1
  adoption point recorded there.
- Program: issue #188; tickets #227 (read surface), #228 (mutations +
  remote sync), #229 (forge PR via gh).

## Context

`herdr-plugins.git/v1` advanced from the Stage-1 dev contract
(`414e87d`, read-only `status`/`diff`/`project`) to the release-0-2-0
implementation (`62309b9c`): `files`, `log`, `compare`, local mutations
(`stage`/`unstage`/`commit`/`branch`/`upstream`), remote sync
(`remote`/`fetch`/`push`), and a GitHub forge surface (`pr
list|status|create|view` via the host `gh` CLI). All remain under the
same `herdr-plugins.git/v1` suffix; `capability` now reports
`read_only: false` and a `mutation_commands` list.

Two compatibility facts matter:

- The Stage-1 dev contract document drifted from its implementation:
  the CLI already emitted `output`/`stat_output`, while the document
  claimed `diff`/`stat`. The release-0-2-0 document matches the
  implementation (`output`/`stat_output`/`name_status_output`/
  `numstat_output`/`paths`/`format`). Clients must therefore read the
  new field names and tolerate the documented-old ones.
- Plugin versions on hosts are heterogeneous: a host may still run the
  Stage-1 build (commands: capability/status/diff/project only) while
  another runs 0.2.x. `capability.commands`/`mutation_commands` is the
  per-host truth — the UI gates each operation on it and never offers
  an action the host's plugin does not advertise.

## Decision

1. **Pin**: herdr-t3 consumes `herdr-plugins.git/v1` as implemented at
   `rebuildup/herdr-plugins@62309b9c` (release-0-2-0 code-complete;
   the later `ledger-status` merge is docs-only). The formal release
   tag is fixed at release-candidate time; the pin, not a moving
   branch, is the adoption point (same rule as ADR-0011).
2. **Read surface first (#227)**: `files` grouped list with
   path-scoped `diff`, `log`, and `compare` complete the read side of
   the contract. `status` output is unchanged between pins and needs
   no migration.
3. **Mutations are explicit-only (#228)**: every mutation is a direct
   user action on the selected pane's repository — no background
   mutation, no implicit commit/push, no plain `--force` (the contract
   exposes only `--force-with-lease`). After each mutation the client
   refetches `status`/`files`; partial failures (hook failure,
   nothing-to-commit, non-fast-forward, missing upstream) surface the
   plugin's `git_error` message, never a fabricated success.
4. **Forge is gh-backed and honestly gated (#229)**: `pr` commands run
   the host's `gh` (minimum 2.81.0, `gh auth` required, `GH_PROMPT_DISABLED`).
   `gh_missing`/`gh_error`/auth failures are displayed with their
   reason. Merge, review comments, CI logs and non-GitHub forges remain
   upstream follow-ups (herdr-plugins#25) — not implemented here.
5. **Inbox semantics unchanged**: `herdr-plugins.inbox/v1` and the
   inbox plugin are byte-identical between `414e87d` and `62309b9c`;
   the #219 migration semantics (ADR-0011 §8) carry over without
   amendment.
6. **Surface**: a per-pane Source Control dialog (WorkspaceHeader pane
   menu) for now. A docked right-panel host is a separate parity item;
   the dialog is not a permanent architecture claim.

## Consequences

- `plugin_call` consumers must treat `capability.commands` and
  `mutation_commands` as the authoritative per-host feature set; UI
  code checks them before enabling operations.
- `fetchGitDiff` and any diff consumer read the 0.2.x field names with
  a fallback for the Stage-1 drift (`diff`/`stat`), so both plugin
  generations work during the rollout window.
- pc-setup#239 owns making `rebuildup.git` installable per host
  (`git` + `bun` prerequisites; `gh` only needed for forge commands).
- #221–#225 map onto `docs/program/feature-ledger.json` @ `62309b9c`;
  upstream-blocked rows (#8 attention granularity, #9 agent-view
  namespacing) gate the corresponding client features, not the git
  surface.
