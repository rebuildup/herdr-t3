# ADR-0016: Checkpoints surface — checkpoints-v1 contract pin and scope

- Status: Accepted
- Date: 2026-11-27
- Extends: ADR-0011 (plugin consumption boundary); same pinning rule as
  ADR-0012/ADR-0014.
- Program: issue #188; ticket #260; groundwork #221 (narrowed to the
  published contract).

## Context

`rebuildup/herdr-plugins` release-0-4-0 (`4aab1a7`) publishes
`herdr-plugins.checkpoints/v1`
(`docs/contracts/checkpoints-v1.md`, plugin `rebuildup.checkpoints`
v0.1.0; upstream herdr-plugins#72): hidden-ref worktree checkpoints —
synthetic commits under `refs/herdr-plugins/checkpoints/<repo-key>/<id>`
with a plugin-side state index. Upstream residuals #73–#75 (restore,
auto-capture, multi-repo orchestration/GC hardening) remain OPEN and are
explicit v1 non-goals.

Facts that shape the client integration:

- Commands are flat words — `capability`, `create`, `list`, `show`,
  `diff`, `delete` — each carried as the `plugin_call` command; unlike
  projects-v1 there are no subcommand argv words.
  `capability.mutation_commands` carries `["create","delete"]` and
  `read_only:false`.
- `create` targets a repo two ways: `--repo PATH`, or a pane id
  positional resolved through the herdr session snapshot (same path as
  `rebuildup.git`). `--repo` and a pane id are mutually exclusive.
- `list --repo PATH` filters by canonical repo root; `show <id>` reports
  `ref.exists:false` while still returning the state entry — a deleted
  or moved hidden ref is surfaced, never hidden.
- `diff <a> <b>` accepts a checkpoint id or literal `HEAD` per side; at
  least one side must be a checkpoint and both checkpoint sides must
  share `repo_root` (`cross_repo` otherwise).
- `delete <id>` is idempotent: the state entry is always removed; the
  hidden ref is deleted only when it still exists, reported via
  `ref_existed:false` + `warnings` when already gone or the repo
  unreachable.
- Error `kind`s: `not_a_repo`, `bare_repo`, `empty_repo`,
  `sparse_checkout`, `unknown_checkpoint`, `cross_repo`,
  `pane_not_found`, `no_pane_cwd`, `git_missing`, `timeout`,
  `git_error`, `usage`.

## Decision

1. **Pin**: herdr-t3 consumes `herdr-plugins.checkpoints/v1` as
   implemented at `rebuildup/herdr-plugins@4aab1a7` (release-0-4-0).
   The formal release tag is fixed at release-candidate time; the pin,
   not a moving branch, is the adoption point (ADR-0011/0012/0014 rule).
2. **One surface**: a single Checkpoints dialog behind one overflow-menu
   entry (`src/components/CheckpointsDialog.tsx` +
   `src/shell/checkpoints.ts`) covering list/show/diff/create/delete.
   All traffic goes through `plugin_call` only — no plugin state file
   reads, no direct git invocation, no Electron dependencies.
3. **Honest gating**: reads gate on `capability.commands`
   (`list`/`show`/`diff`); mutations gate on `mutation_commands`
   (`create`/`delete`). Unsupported commands render
   "not supported by this plugin version"; plugin `error.kind` values
   pass through verbatim.
4. **Honest state**: `ref.exists:false` renders as a "ref missing"
   badge with an explanatory note; `delete` shows `ref_existed` and
   `warnings` verbatim; `diff`/`show` truncation is labelled. No restore
   affordance exists — v1 has none upstream.
5. **Create targets**: the dialog offers the focused pane (positional
   pane id, resolved plugin-side through the session snapshot) or an
   explicit `--repo PATH`; the two are never combined. An optional
   `--label` maps to the entry label.

## Consequences

- pc-setup owns making `rebuildup.checkpoints` installable per host
  (`git` + `bun` prerequisites per `requires`).
- New surface registers in `docs/migration/capabilities.json`
  (`checkpoints.surface`) at `current-verified` for the implemented
  commands; restore/auto-capture/GC stay unimplemented pending
  herdr-plugins#73–#75.
- A host without the plugin (or an older build) yields capability-gated
  UI — boundary unavailability reason or "not supported by this plugin
  version" — never a fake empty list.
