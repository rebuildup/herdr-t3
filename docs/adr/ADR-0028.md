# ADR-0028: Usage surface — usage-v1 contract pin @d23205af and read-only adoption

- Status: Accepted
- Date: 2026-11-27
- Program: issue #188 (T3 parity); ticket #375. Plugin-surface
  consumption of `rebuildup.usage`; same ADR-0011 `plugin_call`
  boundary as ADR-0012/0014/0016/0026/0027.
- Pin: `rebuildup/herdr-plugins@d23205af0cd2ff7dba25f72e1f3b872762a108ee`
  = tag `v0.9.0`, contract `herdr-plugins.usage/v1` (STABLE since
  herdr-plugins v0.5.0). Upstream spec:
  `herdr-plugins/docs/contracts/usage-v1.md`.

## Context

T3 Code parity tracks usage metering (token totals, provider charts,
subscription limits) as a first-class surface; herdr exposes no
token/cost data itself. The `rebuildup.usage` plugin fills exactly
this gap: it aggregates the `rebuildup.conversations` normalized
index (consumed only through that plugin's public read-only CLI
contract — never its state files), probes provider subscription
quota endpoints and CLIProxyAPI-compatible hubs, prices models
against a cached public rate table, and reports quota-vs-measured
divergence — all as honest data, never fabricated numbers.

## Decision

1. Consume the READ surface `capability`, `quota`, `usage`, `cost`,
   `divergence`. The contract is read-only (`read_only: true`,
   `mutation_commands: []`), so `USAGE_MUTATION_COMMANDS` is an
   empty allowlist and `usageSupportsMutation` fails closed — a
   future contract revision that adds writes (e.g. cache GC) must
   extend the allowlist deliberately in its own ticket.
2. `src/shell/usage.ts` mirrors the `conversations.ts` store shape:
   per-machine `{status, quota, quotaError}` state, defensive
   `*FromDoc` parsers that reject foreign contracts and malformed
   documents, the shared
   `not_installed|disabled|incompatible|unreachable|error`
   classification, a TTL-cached capability probe, and refresh on
   snapshot pushes (debounced), machine-status and machine-list
   changes via `initUsage()`. Plugin-side kinds
   (`conversations_unavailable`, `conversations_error`, …) stay
   `error` with verbatim detail; `conversations_unavailable` maps to
   `unreachable` because the index source cannot be reached. A
   missing conversations index is never an error — the plugin
   returns the honest empty result (`totals.events: 0` + `hint`),
   rendered verbatim.
3. `quota` is conversations-index independent, so the store fetches
   it eagerly per machine (mirroring `sessions` in conversations).
   `usage`/`cost`/`divergence` are index-dependent and heavier, so
   they are lazy surface fetches carrying the contract selector args
   (`--pane`/`--session-id`/`--provider`/`--from`/`--to` ISO instants,
   inclusive). A quota failure keeps the machine `ready` with
   `quotaError` and last-good quota — it must not un-render the
   index-dependent reads.
4. Honesty rules rendered verbatim, never re-derived: cache-token
   accounting is a tri-state (`reported`|`unsupported`|`unknown`)
   shown per provider — never collapsed to a zero measurement;
   `thinking_tokens` and `provider_reported_cost_usd` stay `null`
   when unreported; the cost figure always carries the contract
   disclaimer and is labeled a list-price estimate, never a bill;
   `estimate_complete: false` and `unpriced_models[]` disclose
   partial totals; divergence `verdict`s
   (`different_units`|`no_measured_usage`|`quota_unavailable`|
   `no_data`) and `window_alignment` are shown as reported — quota
   windows and transcript tokens are different units and are never
   reconciled or converted.
5. `src/components/UsageSurface.tsx` renders quota provider/hub
   cards (`used_percent`/`resets_at`/plan/`stale`/cache triple),
   usage totals + cache-token rows + a client-side breakdown
   dimension selector over the six contract dimensions, the cost
   estimate block, and divergence comparisons — T3 Code primitives
   and design tokens only. The capability `sources` matrix gates an
   honest "conversations index unavailable" hint when the
   index-dependent commands would return empty.
6. Surface wiring follows the established right-panel pattern:
   `rightPanelStore` union + `isSurface`, `RightPanel`
   icons/titles/content/add-actions, `CommandMenu` and
   `WorkspaceHeader` entries, `initUsage()` in `App.tsx`.

## Consequences

- The usage-metering gap narrows to "plugin-owned aggregation and
  quota probing, GUI renders reports"; provider price-override
  editing (`modelPrices`), pooled cross-provider rollups, and any
  usage-authoring UI remain future tickets with their own contract
  review.
- `usage`/`cost`/`divergence` each re-run the full conversations
  export plugin-side per call; the surface debounces filter changes
  (400ms) and fetches lazily rather than polling.
- Contract pin is recorded here and in
  `docs/migration/contracts/plugin-usage.md` +
  `docs/migration/capabilities.json`; a future contract revision
  re-pins via a new ADR per the established rule.
